# Unauthenticated File Upload Enables Server-Side PHP Execution

**Finding status:** Confirmed (reproduced)  
**Category:** Unrestricted File Upload / Remote Code Execution / Path Traversal  
**CVSS v3.1:** 9.8 — Critical (estimated)  
**Vector:** `CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:H/A:H`

## Vulnerability

A legacy PHP file-management connector was publicly accessible without authentication and accepted unrestricted file uploads into a directory where PHP scripts were executable. The same connector permitted unauthenticated file downloads and path traversal outside the web root.

The server-side authorization hook was effectively disabled:

```php
function auth() {
    return true;
}
```

The configuration also permitted general uploads (`imagesonly = false`). The connector combined request-controlled path values with its document root without sufficient containment checks.

## Technical evidence

1. The public file-management interface and its PHP connector were reachable without an application session.
2. A harmless PHP marker file was uploaded through a multipart request to:

   ```text
   POST /js/filemanager/connectors/php/filemanager.php
   mode=add
   currentpath=/js/filemanager/
   newfile=<controlled_name>.php
   ```

3. The controlled marker contained only:

   ```php
   <?php echo "SAFE_RCE_MARKER"; ?>
   ```

4. A subsequent unauthenticated `GET` to the uploaded file returned the marker generated by **server-side PHP execution**, confirming execution of attacker-controlled PHP code.
5. The test file was immediately removed through the connector's delete action; the same URL then returned `404`.

Read-only connector tests additionally demonstrated direct PHP source disclosure and directory traversal when request-controlled file paths pointed outside the public document root. No sensitive configuration contents were extracted.

## Impact and limits

**Confirmed:** unauthenticated server-side PHP code execution, arbitrary file upload into an executable location, and PHP source disclosure through unrestricted file reads.

**Not attempted:** system command execution, persistence, credential extraction, or database modifications. Later retesting found the tested file-management routes returning `404`, so the originally vulnerable endpoints were no longer reachable at that time.
